บทที่ 01 · Flow รวม

สถานะ Journey เดินหน้าเรื่อยๆ ไม่ย้อนกลับ

Draft→ Invited→ Responded→ Converted (หรือ)Lost
  • 1Draft — อยู่ใน target list แล้ว แต่ยังไม่ถูกเชิญ
  • 2Invited — เชิญแล้ว ระบบพยายามออกคูปองให้อัตโนมัติทันที
  • 3Responded — ลูกค้ากดรับคูปอง/สิทธิ์แล้ว (อัปเดตอัตโนมัติตอนออกคูปองสำเร็จ)
  • 4Converted — ลูกค้าใช้คูปองจริงแล้วที่ POS (อัปเดตอัตโนมัติผ่าน cron ทุก 60 นาที)
ตัวเลข Sent / Opened(Claimed) / Redemptions(Converted) ที่เห็นใน Dashboard และหน้า Campaign นับจากสถานะเหล่านี้โดยตรง

บทที่ 03 · Customer Journey (3/3)

Apply โค้ด → ปิดออเดอร์ตามปกติ → ระบบอัปเดตให้เอง

พิมพ์โค้ด + Apply→ ส่วนลดเข้าออเดอร์→ ปิดออเดอร์ปกติ→ cron ทุก 60 นาที → Converted
  • 1ให้ลูกค้าอ่านโค้ดตัวอักษร (หรือยื่นจอให้ดู) พนักงานพิมพ์เข้าไปตรงๆ กด Apply — ระบบจับคู่คูปองใส่ส่วนลดเข้าออเดอร์ทันที
  • 2พนักงานคิดเงินต่อตามปกติ ไม่มีขั้นตอนพิเศษเพิ่มเติม คูปองถูกใช้ (points เหลือ 0) ทันทีที่ออเดอร์เสร็จสมบูรณ์ — ใบเสร็จแสดงบรรทัดส่วนลดจากคูปองด้วย
  • 3การใช้คูปองที่ POS เกิดนอกระบบ CDP-CM โดยตรง จึงมี cron ทำงานทุก 60 นาที คอยเช็คว่าคูปองถูกใช้หรือยัง — ถ้าใช้แล้ว อัปเดต target เป็น Converted ให้อัตโนมัติ

บทที่ 05 ใหม่ · 2026-07-23 · Automated Journey

ตั้งกฎครั้งเดียว ระบบทำงานให้เองต่อเนื่อง

5
โจทย์
วันเกิดลูกค้า → ได้คูปองวันเกิดอัตโนมัติทุกเดือน / ใช้คูปอง A → ได้ B ต่อ / ซื้อสินค้า A → ได้คูปอง X — ไม่ต้องกลับมากด Add Targets เองทุกครั้ง
Recurring — วันเกิด
Cron รายเดือน (วันที่ 1) → หาลูกค้าเดือนเกิดตรงเดือนนี้ → เช็คสิทธิ์ผ่านระบบ Privilege เดิม (cycle 1 ครั้ง/ปี) → Auto-confirm Privilege Claim ออกคูปองให้ทันที
ไม่ผ่าน Campaign/Campaign Target เลย
Event-based — Coupon Used / Product Purchased
Cron รายวัน → สแกนหาเหตุการณ์ใหม่ (หลังวันสร้าง rule เท่านั้น) → หน่วงตามวันที่ตั้ง (ถ้ามี) → เพิ่มเข้า Campaign Target + Invite ให้อัตโนมัติ → Reward ที่ผูกแคมเปญออกคูปองให้
ผ่าน Campaign Target เหมือน flow ปกติ
Rule ใหม่ไม่ย้อนหลัง: Event-based rule นับเฉพาะเหตุการณ์ที่เกิดหลังจากวันที่สร้าง rule เท่านั้น ป้องกันส่งคูปองจำนวนมากผิดคาดตอนเปิดใช้งานครั้งแรก
บทที่ 05 · ตั้งค่า Automated Journey (1/2)

ตั้งกฎ Recurring สำหรับคูปองวันเกิด

Configuration → Automated Journey Rules → New→ Trigger Type = Recurring→ เลือก Privilege Reward to Auto-Claim
  • 1เลือก Trigger Type = Recurring
  • 2เลือก Privilege Reward to Auto-Claim — ต้องเป็น Reward ที่เปิด "Enable Privilege Claim" ไว้แล้ว และตั้ง Privilege Condition = Birthday Month
  • 3ระบบใช้ Limit Period ของ reward นั้นเป็นตัวกันไม่ให้ออกซ้ำ (ปกติตั้ง "Per Year")

บทที่ 05 · ตั้งค่า Automated Journey (2/2)

ตั้งกฎ Event-based สำหรับ Coupon Used / Product Purchased

Trigger Type = Event-based→ เลือก Target Campaign→ เลือก Event Source→ ตั้ง Delay (days)
  • 1เลือก Target Campaign — แคมเปญที่จะเพิ่มลูกค้าเข้าไปเมื่อเข้าเงื่อนไข (ต้องมี Reward ผูก "Restrict to Campaign" ไว้แล้ว)
  • 2เลือก Event Source: Coupon Used → เลือก Source Coupon Program, หรือ Product Purchased → เลือก Source Product
  • 3ตั้ง Delay (days) — 0 = ส่งทันทีที่ตรวจพบ, ใส่ตัวเลข = หน่วงกี่วันก่อนเพิ่มเข้าแคมเปญ
