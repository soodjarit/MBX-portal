บทที่ 1 · ภาพรวมระบบ

บทที่ 2 · เริ่มต้นใช้งาน

สร้าง Project ใหม่ — เริ่มต้นยังไง

  • 1เมนู Project → Projects → New ตั้งชื่อ Project ตามงานจริง
  • 2ตั้ง Project Code (เช่น MXP, TTT) — ถ้าไม่ตั้งเอง ระบบ auto-gen จากชื่อให้ โค้ดนี้เป็น prefix ของ Task ID ทุกตัวในโปรเจกต์ (เช่น MXP-0552) ทำให้อ้างอิงใน Telegram อ่านง่าย ไม่ใช้ internal ID ของ Odoo ตรงๆ
  • 3Company scope เป็นแบบ federated — ทีมเห็น task ข้าม company ได้ตาม requirement งาน PM ภายใน ไม่ต้องตั้งค่า silo แยกทีละบริษัท
  • 4ปรับ Stage/Kanban ตามที่ทีมต้องการได้อิสระ — ระบบ sync stage อัตโนมัติตามสถานะ task (done/in progress/cancelled) ให้เองอยู่แล้ว
Tips: ตั้ง Project Code ให้สั้นและจำง่ายตั้งแต่ต้น เพราะจะติดไปกับทุก Task ID ที่สร้างในโปรเจกต์นี้ตลอดไป
บทที่ 3 · โครงสร้าง Task

Task แบ่งเป็น 3 ระดับ: Phase → Main → Internal

L1 · Phase
ระดับใหญ่สุด ไม่มี parent — แบ่งโปรเจกต์เป็นช่วงงานหลัก เช่น "Sprint 1", "Phase Design"
L2 · Main
งานหลักภายใต้ Phase — ระดับที่มักใช้ Apply Template สร้าง sub-task ย่อยลงไปอีกชั้น
L3 · Internal
Sub-task ย่อยที่สุด งานจริงที่ assignee ทำต่อวัน — planned hours rollup ขึ้นไปทุกชั้นอัตโนมัติ
H
H-task Breadcrumb
ทุก task แสดงสายพันธุ์ของตัวเองใต้ชื่อเสมอ ทั้งบน Task Form และท้าย Kanban card ไม่ต้องไล่คลิกดู parent เอง — format: Requirement brief to team / ทดสอบสาม / Project
บทที่ 4 · ใช้ Template สร้าง Sub-task อัตโนมัติ

Apply Template — สร้าง Sub-task พร้อม Dependency ในคลิกเดียว

  • 1เปิด task ระดับ Main หรือ Phase → กด ➕ Apply Template บน header
  • 2เลือก Template Set ที่ต้องการ + ใส่วันที่เริ่มโปรเจกต์
  • 3ระบบสร้าง sub-task ทั้งหมดให้ครบ พร้อม dependency chain ต่อกันตามลำดับ และคำนวณวันที่ตาม working days (ข้ามเสาร์-อาทิตย์อัตโนมัติ)

บทที่ 5 · ฟีเจอร์ใหม่ อัปเดต 2 ส.ค. 2026

Recalculate Dates: เลือกเริ่มจาก Sub-task ไหนก็ได้

!
ปัญหาเดิม
ปุ่ม Recalculate Dates เดิม คำนวณทุก sub-task ใหม่หมดทุกครั้ง แม้บางตัวจะทำเสร็จไปแล้ว หรือทีมตกลงวันที่เดิมไว้แน่นอนแล้วก็ตาม — ต้องคอยระวังไม่ให้เผลอเขียนทับงานที่เสร็จแล้ว
  • 1กด 🔄 Recalculate Dates เหมือนเดิม
  • 2เลือก dropdown "เริ่มจาก Sub-task" (ใหม่) — เว้นว่างไว้ = คำนวณทั้งหมดเหมือนเดิมทุกประการ
  • 3ใส่ New Project Start Date → sub-task ที่เลือกจะเริ่มนับจากวันนี้ตรงๆ ตัวที่อยู่ก่อนจุดที่เลือกไม่ถูกแตะเลย ส่วนตัวที่ Done/Cancelled ระหว่างทางก็ข้ามเช่นกัน (แต่ยังใช้วันที่จริงเป็นจุดอ้างอิงให้ตัวถัดไปคำนวณต่อถูกต้อง)

บทที่ 6 · เครื่องมือจัดวันที่อื่นๆ

อีก 3 เครื่องมือช่วยจัดวันที่ นอกจาก Recalculate Dates

📊 Calculate from Sub-tasks
Rollup วันที่ของ task พ่อ ให้ครอบคลุมช่วง earliest start – latest end/deadline ของ sub-task ทั้งหมด — ไม่แตะวันที่ sub-task เอง ใช้ตอนแก้วันที่ sub-task มือแล้วอยากอัปเดต parent ให้ตรง
📅 Adjust Deadline
Wizard เลื่อน deadline แบบ cascade ไปยัง task ที่เกี่ยวข้อง พร้อม suggest ช่องว่างที่ไม่ชนกับงานอื่นของ assignee คนเดียวกัน — PM approve ก่อน apply เสมอ
🔄 Recalculate All (Project)
คำนวณทั้งโปรเจกต์รวดเดียวจากหน้า Project — topo-sort ทุก Phase (L1) ตาม dependency ก่อนไล่ cascade ลง L2→L3 ทีละสาย
Deploy pattern สำหรับทีม dev: ทุกครั้งที่แก้ field/logic การคำนวณวันที่ ต้อง verify ด้วยการเทียบวันที่จริงก่อน-หลังผ่าน RPC เสมอ — "ไม่มี error" ไม่ได้แปลว่า "คำนวณถูก" โดยเฉพาะ logic ที่มีหลาย branch (skip/anchor/cascade) แบบนี้
บทที่ 7 · Dependency & Time Conflict

Blocked By, Time Conflict Check, และ Find Slot

🔗 Blocked By (Dependency)
แท็บ "Blocked By" ใน PTJ Info — เลือก task ที่ต้องเสร็จก่อน (depend_on_ids) ใช้ได้ทุกระดับ ระบบ auto-flip สถานะ + sync Kanban stage อัตโนมัติเมื่อ predecessor เสร็จแล้ว ปลดบล็อกให้เอง
⚠️ Time Conflict Check
ตรวจ overlap ของงานคนเดียวกันแบบ 2 ทาง แสดง risk dot บน Gantt ทันทีที่ชนกัน
🔍 Find Slot
Wizard หาช่องว่างถัดไปที่ assignee ว่างจริง แล้วเลื่อน task + successor ตามให้อัตโนมัติ
บทที่ 8 · Gantt Chart

Gantt Chart — วางแผนภาพรวมทั้งโปรเจกต์

WBS Numbers
คอลัมน์ # แสดงเลข 1, 1.1, 1.1.1 ตามลำดับชั้นจริง เรียง L1 ก่อนเสมอแล้วค่อยไล่ children (DFS)
Drag & Drop จัดลำดับ
ลากจัดลำดับ sibling ได้ตรงๆ ในหน้า Gantt — เขียนค่า sequence ลง DB ทันที
Baseline Overlay
เก็บ snapshot แผนเดิม (Plan Baseline) แล้วโชว์ ghost bar เทียบกับแผนปัจจุบัน เปิด/ปิดได้ตามต้องการ
มี Today Line, Risk Dots (conflict/overdue), Level Filter (เลือกดูเฉพาะ Phase/Main/Internal) ในหน้าเดียวกัน
บทที่ 9 · Dashboard

3 Dashboard สำหรับ 3 บทบาท

My Dashboard
มุมมอง staff — การ์ด "โฟกัสวันนี้" + My Tasks จัดกลุ่มตาม date-bucket (Overdue/This Week/Later) + chat กับ Project Owner ได้ตรงจาก drawer
Project Manager Dashboard
Project Cards (health color) → Team View (performance/drift/overdue ต่อคน) → Project Detail (milestone + task tree + activity feed) — คลิก task เปิด drawer เดียวกันทุกที่
WIP Review
Health ring ต่อ project + Milestone Risk พร้อมเหตุผล (pace, overdue, blocker) + In Progress board sort ตามความเร่งด่วน + Person View ข้าม project

สรุป

  • 1สร้าง Project ก่อนเสมอ ตั้ง Project Code ให้จำง่าย เพราะติดไปกับทุก Task ID
  • 2ใช้ Apply Template แทนสร้าง sub-task มือทีละตัว — dependency + วันที่คำนวณให้อัตโนมัติ
  • 3🆕 Recalculate Dates เลือก "เริ่มจาก Sub-task" ได้แล้ว — งานที่เสร็จไปแล้วไม่ถูกเขียนทับอีกต่อไป
  • 4ติดตามภาพรวมผ่าน Gantt/Dashboard และรับแจ้งเตือน/สั่งงานผ่าน Telegram ได้โดยไม่ต้องเปิดเว็บตลอด
