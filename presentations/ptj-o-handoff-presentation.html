บทที่ 4 · การเข้าถึงโค้ด

ดึงจาก Branch เดียว — อย่าไปยุ่งกับ Branch อื่น

# Branch ของ PTJ-O เท่านั้น git fetch origin delivery/mx-ptj git checkout delivery/mx-ptj # README.md ที่ root ของ branch มีรายละเอียดครบ # (module version, ขั้นตอน UAT, ข้อจำกัดที่รู้อยู่แล้ว)
สำคัญ: Repo ต้นทางเป็น repo ที่ MBX ใช้พัฒนาโมดูลอื่นให้ client รายอื่นด้วย จะเห็น branch อื่นที่ไม่เกี่ยวกับ PTJ-O ปนอยู่ — ใช้เฉพาะ delivery/mx-ptj เท่านั้น branch อื่นไม่เกี่ยวข้องกับการส่งมอบนี้เลย
บทที่ 5 · Tag & Versioning

ทุกรอบส่งมอบมี Tag ตามหลัง diff ย้อนดูได้เสมอ

ค้นหารอบส่งมอบทั้งหมด
Tag ทุกอันขึ้นต้นด้วย mxdevlab/ — ใช้คำสั่งเดียวเห็นทุกรอบที่เคยส่งมา:

git tag -l "mxdevlab/mx-ptj/*"
เลขเวอร์ชัน 19.0.A.B.C
MBX เป็นคนขยับหลัก B (ฟีเจอร์ใหม่/โครงสร้าง) — ถ้าฝั่งทีมปลายทางแก้ไขต่อเอง ให้ขยับหลัก C (hotfix) แทน กันเลขชนกัน และทำให้ทั้งสองฝั่งรู้ทันทีว่าใครแก้จากตัวเลขอย่างเดียว
ตัวอย่างรอบนี้: mxdevlab/mx-ptj/v19.0.1.34.0 — เลขหลังสุด (34) คือหลัก B ที่ MBX ขยับ ยังไม่มีใครขยับหลัก C เลย เพราะเป็นรอบส่งมอบแรก
บทที่ 6 · บทบาทหลังส่งมอบ

พูดให้ชัดตั้งแต่ต้น กันเข้าใจผิดทีหลัง

✅ เป็นของทีมปลายทางแล้ว
หลังรับมอบ ความรับผิดชอบต่อบั๊ก/การดูแลโมดูลนี้เป็นของทีมปลายทางเต็มตัว ไม่ต้องรอ MBX มาแก้ให้
🔁 อยากได้ฟีเจอร์เพิ่ม?
แจ้ง MBX เพื่อเปิดรอบส่งมอบใหม่ — ไม่ใช่การแทรกงานเข้าไปในทีม dev ปัจจุบันที่กำลังทำงานอื่นอยู่
📣 แก้โครงสร้างเอง?
ถ้าเปลี่ยน model/field/security เอง โปรดแจ้ง MBX ล่วงหน้า — มีผลต่อรอบส่งมอบถัดไปที่ MBX จะเตรียมมาให้
ห้าม rebase / force-push บน branch หรือ commit ที่มาจากรอบส่งมอบนี้ — ถ้าจะแก้ต่อให้ commit เพิ่มด้านบนตามปกติ กันประวัติที่ทั้งสองฝั่งอ้างอิงร่วมกันเสียหาย
บทที่ 7 · รอบส่งมอบถัดไป

รอบหน้าจะมาแบบไหน

  • 1MBX พัฒนาต่อใน MX-DEV-LAB (ห้อง lab ภายใน) ตามคำขอฟีเจอร์รอบใหม่
  • 2ก่อนเริ่มรอบใหม่ MBX จะอ่านว่าทีมปลายทางแก้อะไรไปบ้างตั้งแต่รอบก่อน (จาก tag ล่าสุดที่ทีมปลายทางใช้) กันเขียนทับงานที่แก้ไปแล้ว
  • 3Commit ใหม่จะถูก push เข้า branch เดิม (delivery/mx-ptj) พร้อม tag ใหม่
  • 4README.md จะอัปเดตสรุปสิ่งที่เปลี่ยนในรอบนั้น (ภาษาธุรกิจ ไม่ใช่ diff โค้ดดิบ)
  • 5ทีมปลายทาง git fetch + diff เทียบ tag เก่ากับใหม่ เพื่อรู้ว่าต้องเอาอะไรเข้าไปผสมกับของที่แก้เองไปแล้ว
สรุป

สิ่งที่ต้องจำ 3 ข้อ

  • 1ใช้เฉพาะ branch delivery/mx-ptj — branch อื่นในนั้นไม่เกี่ยวกับ PTJ-O
  • 2Tag ขึ้นต้น mxdevlab/ คือรอบส่งมอบจริงจาก MBX เท่านั้น ใช้ diff เทียบรอบก่อนเสมอ
  • 3หลังรับมอบ โมดูลนี้เป็นของทีมปลายทางเต็มตัว — อยากได้อะไรเพิ่มให้แจ้ง MBX เปิดรอบใหม่
README เต็มของแต่ละรอบอยู่ที่ root ของ branch delivery/mx-ptj เสมอ
